# ADR-001 · Start with a transport-independent semantic profile

**Status** — Proposed for experiment in SG-002, subject to approval.

## Decision

Use A2A's existing task and message model where agent-to-agent transport is needed, MCP for authorized tool and resource access, and a provisioned local carrier as an offline comparison. Prototype a narrow inspectable profile in JSON for claims and check outcomes that survive transport boundaries. Compare it with direct A2A and concise prose before adding reusable payload machinery. The architectural direction is hybrid-capable, with explicit scope and evidence at the decision boundary and optional payloads only when measured results justify them.

## Rationale and alternatives

A2A already offers identity context, capability discovery, task state, typed Parts, and Artifacts. The likely unmet requirement is predictable transfer of domain-level meanings such as disputed evidence, test execution versus verdict, or applicability to a specific revision. Existing application schemas may already cover those needs. Direct A2A remains the reuse-first candidate if it preserves semantics and task outcomes with equivalent cost and auditability. CloudEvents is useful for event routing and PROV-O offers provenance vocabulary if their existing consumers warrant them. Neither is needed to start the test.

Concise prose is the compatibility floor and an acceptable result if it performs comparably. Fixed symbolism and negotiated vocabularies are worth comparing when repetition is high. Use Agora's precedent for routine reuse and prose fallback. Defer exchanged executable routines and their trust model. The expected gains depend on actual tokenizers and setup cost. Latent research shows improvements in particular checkpoint, workflow, and hardware conditions. It leaves open whether different vendors expose a compatible interface and whether consequential decisions remain reviewable. Require an inspectable decision record and a safe fallback before any opaque channel influences action.

## Evidence for adoption

Lock numerical thresholds and practical budget on development cases, before the held-out run. The following starting gates are proposed.

- Adopt a shared core only if held-out results show a practical improvement over both direct A2A and prose on the same native A2A binding. Permit each direct reuse control to express the required meanings with its own fixture-specific schema. Target at least a five-percentage-point improvement in strict completion or a 15% reduction in cost per correct completion, with a paired uncertainty interval excluding zero on the improvement metric. For the efficiency path, bound the lower confidence limit on strict completion difference to better than minus two percentage points.
- Require both cross-family directions to pass within the pre-registered tolerance, complete reconstruction of critical status, revision and authority details in the audit sample, zero receiver attempts to dispatch unauthorized actions, and zero unauthorized simulator side effects. Require authorized control actions to succeed under the same gates. Report policy-blocked attempts separately. These gates describe observed fixture performance.
- Add payload extensions only when an ablation against structured data plus ordinary references demonstrates a useful benefit. Include fallback costs, artifact access, auditability, and training or adapter costs where applicable. Use any opaque channel only as optional evidence requiring independently inspectable grounds before consequential action.
- If the study cannot distinguish practical differences, prefer the simpler reuse baseline and report the uncertainty. Keep useful domain-level field conventions local if shared adoption has no demonstrated benefit.
